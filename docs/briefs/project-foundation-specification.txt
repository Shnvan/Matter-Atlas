==================================================
RISKS.md
==================================================

Track technical, educational, and project risks.

Examples:

RISK:
Exact Uno Rev3 component revisions may vary.

Mitigation:
Tie claims to documented revision and clearly label differences.

RISK:
Atomic visualization may teach an inaccurate Bohr model.

Mitigation:
Use probability-cloud visuals and explanatory disclaimer.

RISK:
Single index.html becomes unmaintainable.

Mitigation:
Use strongly separated modules/functions and data-driven rendering.

RISK:
Assembly mode may be difficult on touch devices.

Mitigation:
Pointer Events plus tap/select/place alternative.

RISK:
Trying to model every physical component individually may overload the SVG.

Mitigation:
Group repetitive passives educationally while retaining component references.

For each risk include:

- ID
- Likelihood
- Impact
- Mitigation
- Current status

==================================================
AI WORKFLOW
==================================================

Every future agent should follow approximately this loop:

1. Read AGENTS.md.
2. Read HANDOFF.md.
3. Read TASKS.md.
4. Read relevant architecture/research documents.
5. Inspect current implementation.
6. Select one defined task.
7. Verify uncertain facts before coding.
8. Implement.
9. Test.
10. Update relevant documentation.
11. Update task state.
12. Update HANDOFF.md.

Do not start broad refactors without checking DECISIONS.md.

Do not redo research already recorded as verified unless:
- a conflict is found,
- a source changed,
- or verification quality is insufficient.


==================================================
SOURCE OF TRUTH ORDER
==================================================

When documents conflict, use this priority:

1. Verified official/manufacturer source
2. REQUIREMENTS.md
3. Accepted entries in DECISIONS.md
4. ARCHITECTURE.md / DATA_MODEL.md
5. Current implementation
6. TASKS.md
7. HANDOFF.md
8. Original conversational assumptions

If the source itself invalidates an existing requirement, record the conflict and update the appropriate documents rather than silently working around it.


==================================================
CONTEXT MANAGEMENT
==================================================

Assume future AI agents have limited context windows.

Therefore:

- Prefer linking documents rather than duplicating large blocks.
- Keep HANDOFF.md compact.
- Keep AGENTS.md stable.
- Move detailed research into topic-specific documents.
- Maintain canonical definitions in one location.
- Maintain canonical source metadata in SOURCES.md.
- Maintain canonical component identity in COMPONENT_INVENTORY.md.
- Maintain canonical status in TASKS.md.

Avoid creating five slightly different descriptions of the same fact.


==================================================
DEFINITION OF DONE
==================================================

A feature is not done merely because code exists.

It is done only when:

1. Functional behavior works.
2. Relevant facts are verified.
3. Source references exist where required.
4. Keyboard interaction works.
5. Touch interaction works where applicable.
6. Reduced-motion behavior works.
7. Responsive layout is checked.
8. No console errors are introduced.
9. Relevant documentation is updated.
10. TASKS.md reflects reality.
11. HANDOFF.md allows another agent to continue.
